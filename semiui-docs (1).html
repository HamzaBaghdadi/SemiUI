Why SemiUI

Built to be changed, not just used

Presets, not hard-coding

Colors, spacing, radius and per-component overrides live in one plain object. Ship the default or author your own.

Copied, not imported

button.component.ts
import { Component, Input } from '@angular/core';

export type ButtonVariant =
  'primary' | 'secondary' | 'destructive' | 'danger'
  | 'success' | 'info' | 'warn' | 'help'
  | 'contrast' | 'link';

@Component({
  selector: 'semi-button',
  standalone: true,
  templateUrl: './button.component.html',
  styleUrl: './button.component.css',
})
export class ButtonComponent {
  @Input() variant: ButtonVariant = 'primary';
  @Input() size: 'sm' | 'md' | 'lg' = 'md';
  @Input() disabled = false;
}

Setup

Installation

SemiUI is copied into your project through a CLI, not installed as a compiled dependency. No Tailwind setup is assumed — bring whatever styling approach your app already uses.

Angular 19+Standalone components & the new control-flow syntax
Node 18 LTS+Required by both the Angular CLI and the SemiUI CLI
Any styling setupPlain CSS works out of the box. Tailwind is optional — see the theming guide
@ng-icons/coreOnly needed once you add a component whose preset references an icon

Guide

Presets & theming

A preset is a plain object — no build plugin, no Tailwind requirement. SemiUI's engine reads it and generates the --semiui-* variables every copied component references.

Shape

What a preset actually is

Every preset — built-in or custom — implements the same ThemePreset shape.

theme-preset.d.ts
interface ThemePreset {
  name: string;
  tokens: {
    color: ColorTokens;       // background, foreground, primary…
    spacing: SpacingTokens;   // xs · sm · md · lg · xl
    radius: RadiusTokens;     // sm · md · lg · full
    typography: TypographyTokens;
    comp: ComponentTokens;    // per-component overrides, e.g. comp.button
  };
  darkColor: ColorTokens;     // paired dark-mode palette
  icons: IconMap;             // logical slot → icon reference
}

Custom presets

Writing your own

A preset is just data. Author a new one with the same shape and point semi.config.ts at it — no fork of the library required.

presets/ember.preset.ts
export const Ember: ThemePreset = {
  name: 'ember',
  tokens: {
    color: {
      background: '#fffaf5',
      foreground: '#431407',
      primary: '#ea580c',
      primaryForeground: '#ffffff',
      destructive: '#dc2626',
      destructiveForeground: '#ffffff',
      border: '#fed7aa',
      ring: '#ea580c',
      muted: '#ffedd5',
      mutedForeground: '#9a3412',
    },
    spacing: Semi.tokens.spacing,
    radius: Semi.tokens.radius,
    typography: Semi.tokens.typography,
    comp: Semi.tokens.comp,
  },
  darkColor: { /* paired dark palette */ },
  icons: Semi.icons,
};
semi.config.ts
import { Ember } from './presets/ember.preset';

export default {
  preset: Ember,
} satisfies SemiConfig;
Fine control

Component-level overrides

Beyond the shared palette, tokens.comp lets a preset restyle one component without touching the rest — this is the same object driving the Button page.

excerpt — comp.button
comp: {
  button: {
    radius: '0.5rem',
    fontWeight: '500',
    focusRing: 'var(--semiui-color-ring)',
    backgroundDisabled: 'var(--semiui-color-muted)',
    foregroundDisabled: 'var(--semiui-color-muted-foreground)',
    variants: {
      primary: {
        background: 'var(--semiui-color-primary)',
        foreground: 'var(--semiui-color-primary-foreground)',
      },
      success: { background: '#16a34a', foreground: '#ffffff' },
      // … info, warn, help, contrast, link
    },
  },
}

Dark mode

Where the dark palette comes from

Every preset pairs its light tokens.color with a darkColor object of the same shape. Toggling .dark on the root element is all a project needs to do — SemiUI's generated CSS handles the rest.

theme.service.ts
export class ThemeService {
  toggle() {
    document.documentElement.classList.toggle('dark');
  }
}
Optional

Bridging into Tailwind

SemiUI doesn't set up Tailwind for you. If your project already uses it, you can map the generated variables into your own @theme block by hand — the mapping is entirely on your side.

src/styles.css
@import "tailwindcss";
@import "./semi-theme.css";

@theme {
  --color-primary: var(--semiui-color-primary);
  --color-background: var(--semiui-color-background);
  /* map the rest of --semiui-* the same way, only where you need Tailwind utilities */
}
