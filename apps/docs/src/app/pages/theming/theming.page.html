Theming

Every visual value in SemiUI -- colors, spacing, radii, per-component padding -- is a CSS custom property. There's no build step, no Sass variables, no runtime style recalculation: provideSemiUI() writes one <style> tag, and components read from it with plain var(...).

How it works

A preset is a plain object: a name, a token tree, a dark-mode color override, and default icons. provideSemiUI({ preset }) flattens the token tree into CSS custom properties named --semiui-<path> and injects them as a stylesheet: 

:root {
  --semiui-color-primary: #6366f1;
  --semiui-color-background: #ffffff;
  --semiui-spacing-md: 0.75rem;
  --semiui-comp-button-padding-x-md: 1rem;
  --semiui-comp-button-variants-primary-background: var(--semiui-color-primary);
  /* ...one property per leaf value in the token tree */
}

.dark {
  --semiui-color-primary: #818cf8;
  --semiui-color-background: #0b1220;
  /* only `color` differs between light and dark -- see below */
}

Nested object keys join with -, and camelCase keys become kebab-case -- comp.button.paddingX.md becomes --semiui-comp-button-padding-x-md.

The token tree

Category Contains
color background, foreground, primary, primaryForeground, destructive, destructiveForeground, border, ring, muted, mutedForeground. The only category that differs between light and dark mode.
spacing xs through xl.
radius sm, md, lg, full.
typography fontFamily, fontSizeSm, fontSizeMd, fontWeightMedium.
comp.button radius, fontWeight, focusRing, disabled colors, per-size paddingX / paddingY / fontSize (sm/md/lg/icon), and per-variant background / foreground / border (primary/secondary/outline/ghost/destructive/link).
comp.input Padding, radius, font size, and colors for background/foreground/placeholder/border in its default, hover, focus, and invalid states.

Why only color needs a dark variant

Aurora's component tokens don't hardcode colors -- they reference the palette: comp.button.variants.primary.background is the literal string 'var(--semiui-color-primary)', not a hex code. Change the palette and every component that references it updates automatically, in both modes, with zero duplication. Hover and active states go a step further and skip tokens entirely, using color-mix() against the base color right in the component's CSS: 

.s-button[data-variant='primary']:hover {
  background: color-mix(in srgb, var(--semiui-comp-button-variants-primary-background) 85%, black);
}

If you build your own preset, following the same pattern (reference color.* from component tokens instead of hardcoding) is what makes it work in light and dark mode for free.

Building a custom preset

A preset is just a ThemePreset object -- there's no registration step or build plugin, you can define one anywhere: 

import { ThemePreset } from '@semiui/tokens';

export const MyPreset: ThemePreset = {
  name: 'my-preset',
  tokens: {
    color: { /* the light palette -- background, foreground, primary, ... */ },
    spacing: { xs: '0.25rem', sm: '0.5rem', md: '0.75rem', lg: '1rem', xl: '1.5rem' },
    radius: { sm: '0.25rem', md: '0.5rem', lg: '0.75rem', full: '9999px' },
    typography: { fontFamily: 'Inter, sans-serif', fontSizeSm: '0.875rem', fontSizeMd: '1rem', fontWeightMedium: '500' },
    comp: { button: { /* ... */ }, input: { /* ... */ } },
  },
  darkColor: { /* the dark palette -- same shape as tokens.color */ },
  icons: {
    loading: { type: 'ng-icon', name: 'lucideLoaderCircle' },
    chevronDown: { type: 'ng-icon', name: 'lucideChevronDown' },
    clear: { type: 'ng-icon', name: 'lucideX' },
    passwordShow: { type: 'ng-icon', name: 'lucideEye' },
    passwordHide: { type: 'ng-icon', name: 'lucideEyeOff' },
  },
};

Then use it instead of Aurora:

provideSemiUI({ preset: MyPreset })

The easiest starting point is copying Aurora's source and changing values.

Icons

Every icon a built-in component needs is a required field on IconTokens, not hardcoded in the component -- loading (Button's spinner), chevronDown and clear (Select's trigger and clear button), and passwordShow / passwordHide (Password's reveal toggle). An IconRef is either an ng-icons name or raw SVG: 

{ type: 'ng-icon', name: 'lucideLoaderCircle' }
{ type: 'svg', markup: '<svg>...</svg>' }

If you reference an ng-icons name, register it with provideIcons() from @ng-icons/core -- provideAuroraIcons() is exactly that call for Aurora's default icons, and covers all five out of the box.
