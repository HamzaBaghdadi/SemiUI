Select

A listbox-based select that works with plain values or option objects, supports ngModel, reactive forms, and Signal Forms, and lets you customize every part of its rendering with template slots. Search/filter and a clear button are on by default, the panel animates open and closed, and it flips above the trigger when there isn't room below.

Installation

npx semiui add select

Primitive options

Plain values (strings, numbers) work directly -- no optionLabel needed.

Model value: {{ fruit }}

<s-select [options]="['Apple', 'Banana', 'Cherry']" [(ngModel)]="fruit" placeholder="Pick a fruit" />

Option objects

optionLabel picks which property to display. Without optionValue, the bound value is the whole option object.

Model value: {{ country | json }}

<s-select [options]="countries" optionLabel="name" [(ngModel)]="selectedCountry" placeholder="Select a country" />

Reactive forms

Pick a country and clear it again (via the "x", or Backspace on the trigger) to see the errorMessage -- same input as Text Input and Password, shown once the control is invalid and touched. 

protected reactiveForm = new FormGroup({
  country: new FormControl<Country | undefined>(undefined, Validators.required),
});

<div [formGroup]="reactiveForm">
  <s-select [options]="countries" optionLabel="name" formControlName="country" errorMessage="Please select a country." />
</div>

Signal Forms

Model value: {{ profileModel().country | json }}

protected profileModel = signal({ country: countries[0] });
protected profileForm = form(this.profileModel);

<s-select [options]="countries" optionLabel="name" [formField]="profileForm.country" />

Custom templates

Five named <ng-template> slots: #selected (the closed trigger's content), #option (each row in the list), #icon (replaces the default chevron), and #header / #footer (rendered above/below the list).

Angular's strict template checker can't infer a concrete type for let-option on a content-projected <ng-template> (that requires a structural directive with ngTemplateContextGuard, which is heavier machinery than a simple named slot). Until that's added, wrap property access in $any(option) inside these templates -- it's a compile-time-only cast, the runtime value is still your real option.

@if (option) { {{ $any(option).code }} — {{ $any(option).name }} } {{ selected ? '✓' : '' }} {{ $any(option).name }} ({{ $any(option).code }}) Available Countries 
<s-select [options]="countries" [(ngModel)]="selectedCountry">
  <ng-template #selected let-option>
    {{ '{{ option.code }}' }} — {{ '{{ option.name }}' }}
  </ng-template>
  <ng-template #option let-option let-selected="selected">
    {{ "{{ selected ? '✓' : '' }}" }} {{ '{{ option.name }}' }}
  </ng-template>
  <ng-template #header><strong>Available Countries</strong></ng-template>
</s-select>

Clear and search

Both clearable and filterable default to true -- every select above already has them. clearable shows an "x" once a value is picked; filterable adds a search box to the panel that filters options by label as you type, with filterPlaceholder and emptyMessage to customize the text. Turn either off per instance: 

<s-select [options]="countries" optionLabel="name" [(ngModel)]="selectedCountry"
  [clearable]="false" [filterable]="false" />

Loading

Shows a spinner in place of the chevron and blocks interaction, for async option loading. Dims via opacity rather than swapping to the disabled palette, so it reads as "busy" rather than "unavailable".

<s-select [loading]="true" />

Disabled

Append to body

By default the panel is positioned relative to its own trigger, which breaks if an ancestor clips overflow or creates a new stacking context. Set appendTo="body" to move the panel to a direct child of document.body instead -- it stays pixel-positioned against the trigger, but escapes the clipping container entirely. 

<s-select [options]="fruits" appendTo="body" />

Keyboard

Enter / Space / ↓ / ↑ open the panel; Backspace/Delete on the closed trigger clears the value (when clearable). Once open, focus moves into the search box when filterable is on (letters type normally there), otherwise it stays on the trigger -- either way ↑ ↓ Home End move the highlighted option, Enter selects it (Space too, when the trigger still holds focus), and Escape or clicking outside closes the panel.
